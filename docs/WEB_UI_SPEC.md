# MyApphub Web UI 设计说明

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v1.1 |
| 文档状态 | 已定稿 |
| 适用前端 | Vue 3 + TypeScript + Vite |
| 关联文档 | [产品需求文档](./PRD.md) |

本文档独立定义 MyApphub Web 的视觉、布局、交互状态、响应式与可访问性要求。产品范围、业务规则、接口边界、安全和性能指标以产品需求文档为准。

## 1. Web 视觉定位

Web 定位为“可信、鲜明、具有发布仪式感的私有应用安装页”，不设计成应用商店、营销官网或管理系统。视觉采用“亮暖未来编辑风”：暖银灰环境、应用主色光晕、半透明浅色发布面板、金属 Logo 展示舱和深色通行证式二维码区域。

视觉原则：

- 页面第一视觉必须是应用名称、版本和安装按钮。
- 不展示导航栏、侧边栏、统计或应用推荐；部署者配置的项目名称仅作为页面底部的低调安全署名，默认值为 `MyApphub`。
- 页面背景不是纯色：使用暖米灰基底、克制的网点纹理和由 App 主色生成的柔和环境光。
- App 主色只影响背景光晕、状态光点、更新标记和主按钮，不侵入正文、状态语义色和 Logo 本体。
- 安装主体使用半透明浅色发布面板；桌面二维码使用深暖灰“Access Pass”通行证卡片，形成明确视觉锚点。
- 默认使用系统字体，不从外部字体 CDN 加载资源。
- 动效只用于加载、步骤切换、按钮反馈和复制成功；环境光不循环运动，不使用粒子或宣传动画。
- 页面中不出现“蒲公英”“Fir”等第三方产品名称或视觉元素。

## 2. 基础设计规范

### 2.1 核心颜色

| 用途 | 色值 |
| --- | --- |
| 页面暖色基底 | `#F9F6EF` → `#E5DFD5` |
| 发布面板 | `rgba(255, 254, 250, 0.93)` |
| 通行证卡片 | `#343331` → `#1B1C20` |
| 主文字 | `#161719` |
| 次级文字 | `#696860` |
| 浅色边框 | `rgba(36, 35, 31, 0.14)` |
| 无 Logo 默认主色 | `#986CFF` |
| 成功 | `#16875B` |
| 警告 | `#B7791F` |
| 错误 | `#C0362C` |

### 2.2 App 主色与 Logo 兼容规则

- 有 Logo 时从图标中提取一个候选主色，但必须把饱和度、亮度限制在可读范围后再用于页面环境色；禁止把未经处理的极亮、极暗颜色直接铺满背景。
- 主色提取失败、Logo 为透明单色或结果不满足对比度时，回退到 `#986CFF`。
- Logo 必须原样展示：不改色、不加滤镜、不替换背景、不裁切主体内容。
- Logo 外使用独立的中性金属展示舱。展示舱负责隔离风格冲突，不能要求上传者为适配页面而修改 Logo。
- Logo 图片使用 `object-fit: contain`；上传图标本身已有完整方形背景时可使用 `cover`，但不能裁掉识别主体。
- 无 Logo 时显示稳定兜底图标：取应用名称前两个有效字符作为字母组合，使用默认紫色背景、细线几何纹理和中性金属展示舱。
- 主按钮文字颜色必须根据 App 主色自动选择黑或白，达到 WCAG AA；二维码中心色块可以使用 App 主色，但二维码定位与数据模块保持深色。

### 2.3 字体与字号

- 字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 页面标题：28px/36px，650 字重。
- 应用名称：桌面使用 `clamp(42px, 6vw, 67px)`、0.91 行高、850 字重；手机为 35px、0.96 行高。
- 区块标题：11px/17px，800 字重，使用大写英文标签或简短中文标签并增加字距。
- 正文：15px/24px，400 字重。
- 辅助信息：13px/20px，400 字重。
- UDID、Bundle ID 等技术标识使用系统等宽字体。

### 2.4 间距、形状和层级

- 桌面内容最大宽度：1040px。
- 手机页面左右安全边距：16px。
- 发布面板圆角：28px；手机 24px；主按钮使用胶囊形，输入框圆角 14px。
- 桌面发布面板内边距：30px；手机：20px。
- 主要按钮高度不低于 48px；手机可点击区域不低于 44px。
- Logo 资源：桌面 94×94px，手机 70×70px；外层金属展示舱比资源四周各增加 9px（手机 6px）。
- 主按钮使用当前 App 主色和自动对比文字；按钮右侧固定深色圆形箭头。次按钮使用透明底和细边框；公共页不出现危险按钮。
- 阴影使用暖灰黑，避免纯蓝企业后台风格；金属展示舱允许使用克制的高光渐变。

## 3. 页面路由

Vue Web 只包含以下公开路由：

| 路由 | 用途 |
| --- | --- |
| `/app/:slug` | 应用安装页 |
| `/udid` | iOS UDID 获取工具 |
| `/404` | 分享地址不存在 |

根路径 `/` 不展示公开应用列表，避免泄露私有应用信息；默认跳转到 `/udid`。

## 4. 安装页桌面布局

桌面宽度大于等于 768px 时采用左右两栏：左侧为浅色发布面板，右侧为深色 Access Pass；两栏之间留 16px 间距，不合并为传统白色大卡片。

```text
┌──────────────────────────────────────────────────────────────┐
│ PRIVATE RELEASE · VERIFIED                                     │
│                                                               │
│  ┌──────────────────────────────────┐  ┌───────────────────┐  │
│  │ [金属舱/App图标]  Example Learning │  │ ACCESS PASS / 01  │  │
│  │                  iOS · v2.3.0    │  │   [安装二维码]     │  │
│  │──────────────────────────────────│  │   扫描，继续安装    │  │
│  │ 120 MB      iOS 15+    07.22    │  └───────────────────┘  │
│  │ WHAT'S NEW                       │                         │
│  │ 修复登录问题，优化课程加载速度。    │                         │
│  │ [          直接安装          ↗ ] │                         │
│  └──────────────────────────────────┘                         │
│             SECURELY DISTRIBUTED BY MYAPPHUB            │
└───────────────────────────────────────────────────────────────┘
```

- 页面不设置顶部导航或产品标题；顶部仅保留 `PRIVATE RELEASE · VERIFIED` 状态标签和非敏感发布编号。
- 左栏占约 68%，负责应用信息、更新说明和安装操作。
- 右栏占约 32%，使用深暖灰通行证样式显示二维码和扫码提示。
- 项目名称放在内容底部，作为低对比度安全分发署名；名称通过服务端 `APPHUB_PROJECT_NAME` 配置，支持中文和较长文本。
- 更新说明超过 8 行时折叠，提供“展开全部”。

## 5. 安装页手机布局

宽度小于 768px 时改为单列：

```text
┌────────────────────────────┐
│ MyApphub      私有应用 │
│                            │
│       ┌────────┐           │
│       │ App图标 │           │
│       └────────┘           │
│     Example Learning        │
│       v2.3.0 (105)         │
│                            │
│  大小 120 MB · iOS 15+     │
│                            │
│  更新说明                   │
│  修复登录问题……             │
│                            │
│  [       直接安装        ]  │
│                            │
│  安装说明                   │
└────────────────────────────┘
```

- App 图标、名称和版本保持左对齐横向组合，避免手机端退化成传统应用商店详情页。
- 安装按钮占满内容宽度，并位于首屏可见区域。
- 手机端不显示二维码。
- 主按钮位于版本元数据后，确保首屏可见；更新说明和安装说明紧随按钮下方。
- 适配 iPhone 安全区域，底部内容不能被 Home Indicator 遮挡。

## 6. 分享密码状态

设置分享密码的应用，首次打开时仍展示应用图标、名称、平台和版本，但隐藏更新说明和安装地址。

密码区域采用卡片内嵌形式，不使用弹窗：

```text
┌──────────────────────────────────┐
│ 该应用受密码保护                  │
│ 请输入同事提供的安装密码。          │
│                                  │
│ [ 安装密码                     ] │
│ [         验证并继续            ] │
└──────────────────────────────────┘
```

- 密码输入框支持显示/隐藏切换。
- 按 Enter 可以提交。
- 提交过程中按钮显示加载状态并禁止重复点击。
- 密码错误在输入框下方显示，不清空用户输入。
- 触发限流时显示剩余等待时间，不暴露限流内部规则。
- 验证成功后原位切换为安装内容，不整页闪烁。

## 7. 平台与安装状态

安装页必须覆盖以下状态：

| 状态 | 页面表现 |
| --- | --- |
| 正在加载 | 应用图标、标题、版本位置显示骨架屏，不显示空白页 |
| 正常 Android | 主按钮文案“下载 APK” |
| 正常 iOS | 主按钮文案“直接安装” |
| 电脑访问 | 主按钮保留，同时突出右侧二维码 |
| 平台不匹配 | 黄色提示条说明应使用哪类设备打开 |
| Ad Hoc IPA | 安装按钮下提示设备 UDID 必须已被加入 |
| 企业 IPA | 展示“首次安装如何信任开发者”折叠说明 |
| 描述文件将过期 | 到期前 30 天显示黄色到期提示 |
| 当前无版本 | 禁用安装按钮，显示“暂无可安装版本” |
| 分享不存在 | 进入独立 404 页面，不显示私有应用列表 |
| 分享密码错误 | 输入框下显示错误，不泄露应用文件地址 |
| 安装令牌过期 | 提示“安装链接已过期”，允许重新验证获取 |
| 网络错误 | 提供“重新加载”，保留已经显示的非敏感信息 |

## 8. 安装说明

iOS 企业包安装说明默认折叠，展开后使用三个短步骤：

1. 点击“直接安装”并确认系统安装提示。
2. 首次打开失败时，前往系统设置中的设备管理页面信任企业开发者。
3. iOS/iPadOS 18 及以上若系统要求，重启设备后再次打开。

Ad Hoc 包额外显示“获取 UDID”次按钮，跳转 `/udid`。页面必须说明：获取 UDID 不代表当前包可以立即安装，开发者仍需在 Apple 后台添加设备并重新出包。

Android 安装说明默认折叠，说明浏览器下载完成后如何允许本次来源安装，不要求用户永久开放未知来源权限。

## 9. UDID 工具页面布局

UDID 页使用单卡片步骤流，桌面最大宽度 680px，手机使用单列。

```text
┌────────────────────────────────────────┐
│ 获取设备 UDID                           │
│ 仅用于添加 Apple 测试设备，30 分钟后删除。 │
│                                        │
│  ① 下载描述文件  ─  ② 完成安装  ─  ③ 复制 │
│                                        │
│ 当前步骤说明                             │
│                                        │
│ [          开始获取 UDID              ] │
└────────────────────────────────────────┘
```

页面状态：

1. **环境检测**：非 iOS/iPadOS 或非 Safari 时显示明确提示，禁用开始按钮。
2. **准备阶段**：解释会安装一个临时描述文件，并明确不会长期保存设备信息。
3. **下载阶段**：创建 Challenge 后触发 `.mobileconfig` 下载，显示进入设置的步骤。
4. **等待阶段**：用户返回 Safari 后自动轮询；使用轻量进度动画和“仍在等待安装结果”。
5. **成功阶段**：以等宽字体完整显示 UDID，提供醒目的“复制 UDID”按钮。
6. **复制成功**：按钮短暂切换为“已复制”，同时删除服务端临时结果。
7. **过期或失败**：说明原因并提供“重新开始”，不能展示调用栈或技术错误码。

## 10. Vue 前端技术边界

- 使用 Vue 3 和 TypeScript。
- 使用 Vite 构建。
- 使用 Vue Router 管理公开路由。
- 页面状态使用组件内状态和组合式函数，不引入 Pinia。
- 可以使用一个经过锁定版本的小型二维码生成库；不能调用外部二维码服务。
- 不引入大型 UI 组件库，基础组件使用项目内 Vue/CSS 实现。
- 所有 API 请求封装在统一客户端，处理超时、错误格式和令牌过期。
- Vue 构建产物保留在独立的 `web/dist` 目录，由静态服务器单独托管；Go 服务不读取前端文件。Web 通过构建变量配置 API Origin，生产环境不需要运行 Node 服务。
- 前后端使用不同 Origin 时，静态站点的 CSP `connect-src` 与 `img-src` 必须包含 API Origin，同时服务端 CORS 白名单必须包含 Web Origin。

## 11. 可访问性与兼容性

- 正文与背景颜色对比度符合 WCAG AA。
- 输入框、按钮和折叠内容支持键盘访问及清晰焦点样式。
- 状态不能只依赖颜色表达，同时配合图标或文字。
- 复制成功、密码错误等动态信息使用 `aria-live` 通知读屏软件。
- 遵循 `prefers-reduced-motion`，减少非必要动画。
- 支持最近两个主要版本的 Safari、Chrome 和 Edge。
- 重点实机覆盖 iPhone Safari 和常见 Android Chrome。
